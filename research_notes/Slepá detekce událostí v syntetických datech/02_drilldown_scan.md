# Drill-down / root-cause localisation and scan statistics for a diluted cell-level effect (miss (a): −20 % ramp in one city × channel)

Scope note: 17 tool calls. Primary sources read in full text: RiskLoc (Kalander 2022, arXiv PDF), Neill JRSS-B 2012 (fast subset scan / LTSS), Neill IJHG 2009 (empirical comparison and calibration of scan statistics). Everything else comes from abstracts, repo READMEs or search snippets, and is marked that way where it matters.

## Q1. Multidimensional root-cause localisation (Adtributor, iDice, HotSpot, Squeeze/PSqueeze, AutoRoot, RiskLoc, BALANCE, CMMD …): assumptions, behaviour on ramps, Python code

### Takeaway
All of the "AIOps" localisers solve a different problem from miss (a). They start after an anomaly has already been detected in the aggregate KPI, and they explain one time interval by comparing actual with forecast values per leaf, assuming the ripple effect. They do not detect anything. They can still be used blind on a fixed post-window (sum of actual vs sum of forecast over, e.g., the last 30–60 days), which suits a ramp better than a single timestamp does. RiskLoc, and to a lesser degree Squeeze, are the only ones built for "insignificant-magnitude", fine-grained leaf anomalies. Adtributor is structurally unable to return a city × channel pair.

### Cited Findings
- **Problem formulation shared by the family.** "When an anomaly is identified in an aggregated measure, we want to localize the combination of attributes and attribute values…". Each element has an actual value v(e) and a forecast value f(e) "from a forecasting algorithm, e.g., Prophet, ARMA". RiskLoc aggregates "the actual values of all leaf elements … for the anomaly time interval and the forecast values are computed from historical data", so the input is one interval and not a series. — [RiskLoc, Kalander 2022, arXiv:2205.10004](https://arxiv.org/abs/2205.10004)
- **Ripple effect (HotSpot, Sun et al. 2018).** A root-cause element e_r changes every descendant leaf in proportion to its forecast: (f(e)−v(e))/f(e) = (f(e_r)−v(e_r))/f(e_r). Squeeze (Li et al. 2019) generalised it (GRE) by replacing f with (f+v)/2 so that zero forecasts are allowed. — [RiskLoc §3.2](https://arxiv.org/pdf/2205.10004)
- **Adtributor (Bhagwan et al., NSDI 2014).** Uses explanatory power, succinctness and surprise (how much a dimension's distribution shifts relative to expectation) to pick the dimension most likely responsible for a revenue change. Authors report >95 % accuracy on their ad data. — [USENIX NSDI'14](https://usenix.org/conference/nsdi14/technical-sessions/presentation/bhagwan), [PDF](https://microsoft.com/en-us/research/wp-content/uploads/2016/02/main-14.pdf)
- "Adtributor can only identify root causes that lie within a single attribute." R-Adtributor (the recursive version) covers multiple attributes, but "the stop condition for the recursion is hard to adjust correctly" and it often returns "inexact and verbose root cause sets". — [RiskLoc §1–2](https://arxiv.org/pdf/2205.10004)
- **iDice (Lin et al., ICSE 2016).** Pruning strategies for emerging issues in issue reports. It "assumes a low number of root cause elements" and "will thus perform poorly in more complex situations". — [RiskLoc §2](https://arxiv.org/pdf/2205.10004)
- **HotSpot (Sun et al., 2018).** Monte Carlo tree search plus a ripple-effect-based potential score. It "can be slow" and has difficulty with root causes "involving elements with many attributes or multiple elements". HotSpot and iDice handle only fundamental (additive) measures. — [RiskLoc §2](https://arxiv.org/pdf/2205.10004)
- **Squeeze (Li et al., ISSRE 2019).** Proposed because earlier methods "may miss elements that have insignificant anomaly magnitudes". It runs density clustering on leaf relative residuals, then a top-down search per cluster with a generalised potential score. Weaknesses: it assumes one root cause per cluster, it depends on clustering parameters, and its ranking heuristic "fails for the most fine-grained elements and can result in numerous false positives". — [RiskLoc §2](https://arxiv.org/pdf/2205.10004). The original paper reports an F1 gain of about 0.4 and about 10 s localisation time. The Squeeze repo README warns of "two known severe issues" where the code does not follow the paper. — [NetManAIOps/Squeeze](https://github.com/NetManAIOps/Squeeze)
- **PSqueeze (journal extension, JSS 2023).** Adds probabilistic clustering and detection of "external root causes". Reports +32.89 % F1 on average at about 10 s. — [arXiv:2305.03331](https://arxiv.org/abs/2305.03331), [NetManAIOps/PSqueeze](https://github.com/NetManAIOps/PSqueeze)
- **AutoRoot (Jing et al., 2021).** Parameter-free clustering on top of Squeeze, but it "cannot identify multiple elements in the same root cause and is still highly dependent on clustering accuracy". — [RiskLoc §1–2](https://arxiv.org/pdf/2205.10004)
- **RiskLoc.** Two-way partitions leaves by deviation score into normal and abnormal, weights them by distance from the partition point, and scores risk = r1 (weighted share of an element's leaves in the abnormal partition) combined with r2 (how well the leaves follow the ripple effect). It iterates until the abnormal divergence is explained. It assumes forecasts are "reasonably accurate" (normal deviations centred on zero) and that anomalous leaves share one sign. — [RiskLoc §4](https://arxiv.org/pdf/2205.10004)
- **Benchmark (RiskLoc Table 3, F1).** On dataset L, which contains only finest-layer (leaf-level) anomalies that are "typically insignificant compared to the numerous normal elements": Adtributor 0.00, R-Adtributor 0.009, HotSpot 0.18, Squeeze 0.35, AutoRoot 0.53, RiskLoc 0.68. On the hardest semi-synthetic set A★: RiskLoc 0.46 vs Squeeze 0.30. RiskLoc runs in "less than 3 seconds on average on the simpler datasets". Adtributor is fastest but its "accuracy is inadequate for all but the simplest root causes". — [RiskLoc §5](https://arxiv.org/pdf/2205.10004)
- **Python implementations.** The [shaido987/riskloc](https://github.com/shaido987/riskloc) repo implements RiskLoc, AutoRoot, RobustSpot, Squeeze, HotSpot, Adtributor and R-Adtributor. Dependencies are pandas, numpy, scipy, kneed, loguru and pyyaml, and it runs as `python run.py riskloc --run-path file.csv`. The input is a CSV of leaf elements with real and predict columns, i.e. one snapshot. — [repo README](https://github.com/shaido987/riskloc)
- **CMMD (Yan et al., KDD 2022).** A GNN models how a KPI is computed from base metrics, then a genetic algorithm searches for abnormal dimensions. Deployed in Azure. — [arXiv:2203.16280](https://arxiv.org/abs/2203.16280)
- **BALANCE (Chen et al., Ant Group).** The source is a 2023 arXiv paper, not 2022. It treats RCA as Bayesian sparse linear attribution, which handles correlated candidate causes. — [arXiv:2301.13572](https://arxiv.org/abs/2301.13572)

### Inferences
- **Why parent-gated drill-down misses (a).** This is arithmetic, not cited. If physical stores are a share s of city X's orders, a −20 % cell effect moves the whole-city series by −0.2·s (e.g. −7 % for s ≈ 1/3). Spread over a 30-day ramp, that falls inside seasonal noise. The whole-channel series moves by about −0.2/10 = −2 % with 10 cities. The ripple-effect literature assumes the reverse situation: a detected aggregate anomaly, with the localiser deciding how far down to go. None of these methods opens a pair whose parents show no change point. RiskLoc's own remark that opposite-sign leaf anomalies "cancel each other when aggregating and are thus less likely to be detected" is the same dilution problem stated from the other side.
- **Running localisers on ramps.** Feed them a window aggregate: v = sum over the last W days, f = sum of the baseline forecast (STL or seasonal-naive, or a counterfactual scaled from the rest-of-population). The ramp then simply becomes a smaller average deviation, about −10 % over a window that covers the ramp, and −20 % once the plateau is reached. Single-timestamp use would be very noisy at about 150 orders/day per segment.
- **Role in the pipeline.** These are useful as an explanation layer ("which leaf combination explains the deviation of this window?") after a scan has raised an alarm. They are not detectors, and none of them outputs a calibrated p-value or z. RiskLoc is the one to borrow, if any, because it is the simplest, has Python code and works best on fine-grained leaves.
- **Methods to drop.** Adtributor is unsuitable for pairs by design. iDice, HotSpot, CMMD and BALANCE add complexity (MCTS, GNN, Bayesian selection) without solving detection, and they are harder to explain to students.

### Gaps
- Not verified from primary sources for MID, RCSF, "Hierarchical Pruning", ImpAPTr or RobustSpot. No time spent; none of them changes the "needs a detected aggregate anomaly" premise as far as RiskLoc's survey shows.
- Not found: any benchmark of these localisers on gradual ramps. All the benchmarks use injected step anomalies at one timestamp.

## Q2. Scan statistics (expectation-based Poisson, Kulldorff, LTSS, MD-Scan, FGSS, MBSS): how to scan all city × channel cells and how to calibrate to about 1 false alarm per year

### Takeaway
The expectation-based Poisson (EBP) scan is the method that fits this setting directly. For each candidate cell S (or a subset of cells) and each recent window W, it compares the observed count C with the expected baseline B: F = C·log(C/B) + B − C, or the mirror image for decreases. It is a likelihood-ratio statistic for "the counts in S are multiplied by q". Neill's LTSS property makes the best subset of attribute values exact in O(N log N): sort by C/B and take the top-k. MD-Scan and FGSS extend this to several categorical attributes at once. Neill's own empirical study recommends calibrating by the empirical distribution of the daily maximum score on historical (null) data, not by randomization. That maps directly onto the existing placebo-in-time approach.

### Cited Findings
- **EBP (Neill et al. 2005).** First "computes the expected count b_it … by time series analysis, and then compares actual and expected counts". The log-likelihood ratio is F(S) = C log(C/B) + B − C if C > B (0 otherwise), where C = Σ c_it and B = Σ b_it over region S "for the given time interval". The alternative H1(S) assumes counts in S "are increased by some multiplicative factor". — [Neill, JRSS-B 2012, §2.1](https://www.cs.nyu.edu/~neill/papers/jrssb2012.pdf)
- **LTSS property.** F(S) is maximised over all 2^N subsets by ordering records by a priority function and checking only the top-k sets: O(N) after sorting, O(N log N) in total. For EBP and Kulldorff the priority is c_i/b_i. Many exponential-family expectation-based statistics satisfy LTSS. — [Neill JRSS-B 2012](https://www.cs.nyu.edu/~neill/papers/jrssb2012.pdf); extension to the whole exponential family plus priors on inclusion: [Speakman et al., Penalized Fast Subset Scanning, JCGS 2016](https://www.cs.nyu.edu/~neill/papers/pfss2016.pdf)
- **Temporal windows.** "we scan over varying temporal windows consisting of the most recent W time steps". For a fixed W, LTSS also holds over subsets of data streams with priority c_m/b_m. The paper reports about 0.04 s per day of data for space-time scans. — [Neill JRSS-B 2012 §§3–5](https://www.cs.nyu.edu/~neill/papers/jrssb2012.pdf)
- **MD-Scan (Neill & Kumar, OJPHI 2013).** "jointly optimizes the likelihood ratio statistic over subsets of the values for each monitored attribute" (e.g. zip code × prodrome × gender × age). Its runtime, "while 9× slower than MLTSS, was still extremely fast". — [OJPHI 2013](https://ojphi.jmir.org/2013/1/e61068/PDF)
- **FGSS (McFowland, Speakman & Neill, JMLR 2013).** Searches over subsets of records and attributes in general categorical data with a nonparametric scan statistic. Faster and more powerful than three competing detectors. — [JMLR v14](https://jmlr.org/papers/v14/mcfowland13a.html). A related multivariate space-time subset scan: [Neill, McFowland & Zheng, Stat Med 2013](https://www.cs.nyu.edu/~neill/papers/StatMed2013.pdf)
- **Python implementation.** AIF360's `MDSS_bias_scan` (multi-dimensional subset scan, from Zhang & Neill) accepts `scoring` = 'Bernoulli', 'Gaussian', 'Poisson', 'BerkJones' or a custom ScoringFunction, takes `expectations`, and does random restarts (`num_iters`). — [AIF360 docs](https://aif360.readthedocs.io/en/latest/modules/generated/aif360.sklearn.detectors.MDSS_bias_scan.html), [source](https://github.com/Trusted-AI/AIF360/blob/master/aif360/sklearn/detectors/detectors.py). The Poisson formula in that code was not verified.
- **Kulldorff space-time permutation scan (PLoS Med 2005).** Needs only case counts, "adjusts for natural purely spatial and purely temporal variation", is prospective, and is implemented in SaTScan (free, not Python). — [PLoS Med 2005 / PMC548793](https://pmc.ncbi.nlm.nih.gov/articles/PMC548793), [SaTScan](https://surveillance.cancer.gov/satscan). An R package `scanstatistics` also exists. — [docs](https://search.r-project.org/CRAN/refmans/scanstatistics/html/scan_permutation.html)
- **Calibration evidence (Neill, IJHG 2009).** On outbreak-free days with R = 100 replications, randomization p-values were badly miscalibrated on the OTC datasets: "false positive rates ranging from 11–57 % at α = .05". Only the two Poisson methods on the ED dataset came out near 5 %. Proposed alternative: "learn a threshold on the region score F(S) empirically, using the 100(1−α) percentile of the historical data". The comparison was made at α = .0329, i.e. 1 false positive per month. Randomization "does not improve the detection power … and in most cases significantly harms performance". Final recommendation: discontinue randomization testing "when sufficient historical data is available for empirical calibration". EBP is recommended over Kulldorff's statistic. Fitting a Gumbel distribution to the maximum scores (Abrams et al.) is mentioned as another fix. — [Neill, IJHG 2009, 8:20](https://www.cs.nyu.edu/~neill/papers/ijhg09.pdf)
- The 2006 space-time work found that expectation-based scans outperformed population-based ones at 1 false positive per month. — [Neill thesis, CMU-CS-06-142](https://www.csd.cmu.edu/sites/default/files/phd-thesis/CMU-CS-06-142.pdf)

### Inferences
- **Concrete recipe for miss (a)** (my design; each component is cited above).
  1. Leaf cells are city × channel (30 cells), plus optionally other depth-2 cuboids.
  2. Baseline b_{cell,t}: either a seasonal forecast, or better a DiD-style counterfactual, b = (cell's pre-period share of the rest-of-city/rest-of-channel totals) × the actual rest totals on day t. This absorbs the winter peak, holidays and Black Friday automatically.
  3. Score the decrease version of EBP, F = C log(C/B) + B − C with C < B, for windows "last W days" or [τ, τ+W) with W ∈ {14, 30, 60, 90} and τ on a coarse grid (weekly). The ramp then simply shows up as a growing deficit. An optional ramp template (expected q_t falls linearly to q over 30 days) is a one-parameter GLR that is still cheap to compute.
  4. Use LTSS within each dimension (sort cities by C/B for a fixed channel) to allow "city subset × channel", which keeps the explanation simple.
- **Calibration to about 1 false alarm/year.** Compute max_{cells, windows} F on placebo dates (pre-event periods, or the series with the cell's own history shifted). Set the threshold at the 1 − 1/(number of independent looks per year) quantile, or fit a Gumbel to the maxima to extrapolate the tail. Taking the maximum over all cells and windows is what controls multiplicity across about 300 series; no Bonferroni is needed. This is the same logic as the existing placebo-in-time z, applied to the scan maximum.
- **Explainability.** C, B and q̂ = C/B are directly a relative DiD ("orders in Brno physical fell to 0.80× the expected count"), and C and B each come from a GROUP BY. An SQL sketch in DuckDB:
  `SELECT city, channel, SUM(n) FILTER (WHERE d >= :t0) AS C, SUM(n_expected) FILTER (WHERE d >= :t0) AS B FROM cell_daily GROUP BY ALL ORDER BY C/B`
- **Compute cost.** About 300 cells × about 10 windows × about 100 start points is about 3·10^5 sums. Vectorised with cumulative sums in numpy this takes well under 1 s, so the <60 s budget holds easily, even with 1000 placebo replicas if cumsums are reused.
- **Overdispersion.** Daily order counts with weekly seasonality are overdispersed relative to Poisson. Use EBG or a negative-binomial expectation-based score (both satisfy LTSS per Speakman et al. 2016), or rely on empirical calibration, which absorbs the overdispersion anyway.

### Gaps
- MBSS (multivariate Bayesian scan statistic, Neill et al.): no primary source fetched. It is a Bayesian alternative that outputs posterior probabilities instead of a likelihood ratio, and is likely too heavy to justify here.
- The exact EBP formula for decreases was not quoted. The paper gives the increase version. The decrease version follows by symmetry (score when C < B), but this is not sourced.

## Q3. Alternative: always test all pair cells (with hierarchical FDR) instead of parent-gated drill-down; is gating a known failure mode?

### Takeaway
Exhaustive enumeration of depth-2 cells is cheap at this size (a few hundred series), so parent-gating buys nothing computationally and is exactly what causes miss (a). The scan or localisation literature never gates on the parent having a change point. The DIFF/MacroBase line of work enumerates attribute combinations with GROUP BY/CUBE directly. Hierarchical (tree) FDR procedures such as Yekutieli's are themselves top-down gated, so they would reintroduce the dilution miss. A global max-statistic threshold, or plain BH over all cells, is better here.

### Cited Findings
- **Cost of the search space.** RiskLoc notes that the full space of attribute combinations is infeasible "for even reasonably small d and n" in AIOps settings with millions of leaves (dataset H has 24 million leaf elements). — [RiskLoc](https://arxiv.org/pdf/2205.10004). That is several orders of magnitude larger than 10 cities × 3 channels × a few other dimensions.
- **DIFF (Abuzaid et al., PVLDB 2018).** An explanation operator semantically equivalent to a parameterised relational query of UNION, GROUP BY and CUBE. It outputs attribute combinations with a ratio column (risk ratio), support and outlier count, and is implemented in MacroBase SQL. — [PVLDB paper](https://people.eecs.berkeley.edu/~matei/papers/2019/vldb_macrobase_diff.pdf), [MacroBase SQL docs](https://macrobase.stanford.edu/docs/sql/docs/)
- **Yekutieli (JASA 2008, 103:309–316), hierarchical FDR.** Hypotheses form a tree, testing proceeds top-down and only descends into children of rejected parents. FDR among outer nodes is controlled at 2·D·q·δ* under independence. — [EconPapers](https://econpapers.repec.org/RePEc:bes:jnlasa:v:103:y:2008:m:march:p:309-316); survey and extensions: [Lynch & Guo 2016](https://arxiv.org/abs/1612.04467), [Bogomolov et al., Testing hypotheses on a tree](https://arxiv.org/pdf/1705.07529). R implementation: [structSSI](https://cran.r-project.org/web/packages/structSSI/structSSI.pdf). No Python package was found.
- **Dilution in aggregation.** "anomalies with conflicting sign … cancel each other when aggregating and are thus less likely to be detected". Squeeze was motivated by earlier methods missing "elements that have insignificant anomaly magnitudes". — [RiskLoc](https://arxiv.org/pdf/2205.10004)

### Inferences
- **Recommendation.** Score every depth-2 cell (and depth-1 series) in one pass. Control false alarms by the null distribution of the maximum score across the whole family, estimated from placebo-in-time. Then deduplicate hierarchically: if city X and the pair (X, physical) both fire, report the most specific node that explains most of the deficit (RiskLoc/Squeeze-style "explanatory power" or a simple rule, child q̂ ≪ siblings' q̂). That keeps "parent → child" as an explanation step rather than a detection gate.
- **Size of the depth-2 family.** For example city (10) × channel (3) × segment (4) × category (8) × courier (3) gives 30+40+80+30+12+24+9+32+12+24 ≈ 293 pair cells. Many will be thin, around 5–15 orders/day, so require a minimum expected count (e.g. B ≥ 300 per window) to avoid noise finds.
- **Simpson-like failure of parent-gating.** No paper was found that names this the "Simpson" failure for drill-down. It is best described as dilution or masking. The RiskLoc L-dataset numbers (Adtributor F1 = 0 on leaf-only anomalies) are the closest empirical evidence that top-down, single-dimension attribution misses fine-grained effects.

### Gaps
- Not found: a paper benchmarking "enumerate all cells + max-stat" against "gated drill-down" for business KPIs. The argument above is structural.
- The power loss of Yekutieli's procedure when parents are null is inferred from its top-down design, not quoted from a paper.

## Q4. Recommended 2–4 methods, ranked for this setting, with cost and implementation

### Takeaway
1. An expectation-based Poisson/NB window scan over all depth-2 cells, with a DiD-style baseline and empirical max-score calibration. This is the direct fix for miss (a).
2. An LTSS/MD-Scan subset extension, which finds "cities {A,B} × physical" and is still exact and fast.
3. RiskLoc on window aggregates, as an optional explanation and deduplication layer.
4. Do not use Adtributor, HotSpot, iDice, CMMD or BALANCE as detectors for this miss.

### Cited Findings
- EBP is preferred over Kulldorff, and empirical calibration over randomization. — [Neill IJHG 2009](https://www.cs.nyu.edu/~neill/papers/ijhg09.pdf)
- LTSS is exact in O(N log N), and space-time scans run at about 0.04 s per day of data. — [Neill JRSS-B 2012](https://www.cs.nyu.edu/~neill/papers/jrssb2012.pdf)
- MD-Scan is "extremely fast" for multi-attribute subsets. — [OJPHI 2013](https://ojphi.jmir.org/2013/1/e61068/PDF). A Python MDSS is available in [AIF360](https://aif360.readthedocs.io/en/latest/modules/generated/aif360.sklearn.detectors.MDSS_bias_scan.html).
- RiskLoc has the best F1 on fine-grained leaf anomalies (0.68 on L), runs in under 3 s, and has Python code. — [RiskLoc](https://arxiv.org/pdf/2205.10004), [repo](https://github.com/shaido987/riskloc)

### Inferences
- **Comparison table** (derived from the findings above):

| Method | Detects diluted cell? | Ramp OK? | Calibrated number | Cost here | Python |
|---|---|---|---|---|---|
| EBP/EBG window scan over all cells + empirical max calibration | Yes (no gating) | Yes, via windows or ramp template | Yes (q̂=C/B is the DiD; threshold from placebo maxima) | <1 s numpy cumsums | Write yourself (~50 lines) |
| LTSS / MD-Scan subsets | Yes, also multi-value subsets | Same as above | Yes | O(N log N) per window | AIF360 MDSS or ~30 lines |
| RiskLoc (window aggregate) | Only localises after an alarm | Yes if window-aggregated | No p-value | <3 s per call | shaido987/riskloc |
| Squeeze/PSqueeze/AutoRoot | Localise only, clustering-sensitive | Same | No | ~10 s | riskloc repo, NetManAIOps |
| Adtributor | No (single attribute) | Single interval | No | fastest | riskloc repo |

- **For students.** "For every shop type in every city we compare what we sold with what we would have expected from the rest of the business. The deficit with the largest likelihood ratio wins, and we know how large a ratio pure chance produces because we computed it on 600 days where nothing happened." Each alarm comes with C, B, q̂ and one GROUP BY query.
- **Interaction with the existing z ≥ 5.25 gate.** The scan can serve as a candidate generator for pair cells. The existing relative-DiD plus block-bootstrap plus placebo-z then remains the final confirmation, so the false-find rate of the reporting stage is unchanged and only recall improves.

### Gaps
- No source measured the power of an EBP scan for a −20 % effect at about 50 orders/day per cell with a 30-day ramp. This should be checked by simulation on the project's own data (a placebo plus injected-effect test).
